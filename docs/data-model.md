# データモデル

フィールドの正式な定義はGoバックエンドのスキーマ（APIの型定義）が正。ここにはWebが前提にしている制約と、失効・再発行など履歴の扱いの方針だけを書く。

## 証明書

| 項目 | 制約・方針 | 関連 |
| --- | --- | --- |
| 証明書番号 | 公開用の短い番号。英数字10文字、紛らわしい文字を除く。表示は `XXXXX-XXXXX` | [decisions/0005](decisions/0005-certificate-number-format.md) |
| 状態 | 有効・失効・再発行済みのいずれか。再発行済みは後継の証明書番号を持つ | 下の「履歴の方針」 |
| 発行日時・記録期間・記録回数 | 発行時点で確定し、後から変わらない | [decisions/0003](decisions/0003-certificate-snapshot.md) |
| 端末情報 | メーカー、モデル、SoC、Androidバージョン | ― |
| 評価 | 総合評価、項目別の評価と説明文。バックエンドが算出して返す | [decisions/0008](decisions/0008-grade-on-backend.md) |
| 記録 | 記録日時、計測値（サイクル回数、残容量、温度、消費電力、稼働時間）、ハッシュ、トランザクションハッシュ | [features/verification.md](features/verification.md) |
| 出品先 | フリマ名、商品ID、登録日時、製造番号の末尾（出品者申告）。発行後に追加・変更できる唯一の項目 | [decisions/0006](decisions/0006-listing-link.md) |
| 整備記録 | 記録者（事業者名と種別）、日時、内容（修理箇所・使ったパーツ・点検結果など）。事業者向けサイト（別リポジトリ）が書き込み、Webは表示するだけ。項目とハッシュの対象にするかは事業者向けの要件定義とGoで決める | [decisions/0009](decisions/0009-partner-site-separate-repo.md) |

## 履歴の方針

- 証明書は発行時点のスナップショット。発行後に記録や評価は変わらない。内容を更新したいときは再発行して新しい番号を振る
- 失効・再発行しても証明書は消さない。状態を変えて残し、再発行済みなら後継へのリンクを持たせる
- 出品先は記録データではないので、ハッシュの対象外でチェーンにも載らない。改ざんされていないことの保証は、アプリからしか登録できないこと（本人確認）に頼る（[security.md](security.md)）
- 失効の条件（売却完了時、再発行時など）と、誰が失効させるかはアプリ・Goと要相談

## ブックマーク（ブラウザ内）

[decisions/0002](decisions/0002-bookmark-in-browser.md) の案Aでは、ブックマークをブラウザのlocalStorageに保存する。

| 項目 | 内容 |
| --- | --- |
| 保存するもの | 証明書番号、保存日時、メモ |
| 保存しないもの | 機種名や評価などの中身。一覧を開くたびにAPIから取り直し、失効などの変化を反映する |
| 形式 | バージョン番号付きのJSON。将来アカウント同期（案B）に移すときの変換に使う |
