# 0001 改ざん検証はブラウザで行う

- ステータス：提案中
- 日付：2026-10-28
- 関連：FR-08、FR-09、[features/verification.md](../features/verification.md)

## 背景

証明書の記録が改ざんされていないことを、買い手にどう示すかを決める必要がある。

## 選択肢

- A：ブラウザでデータ本体のハッシュを再計算し、Sepolia上の記録と照合する
- B：Goが検証結果を返し、Webはそれを表示するだけ

## 決定（案）

Aを採る。Bの結果は補助として並べて表示してよい。

## 理由

運営者を信用しなくても確かめられることが、ブロックチェーンを使う理由そのもの。Bだけだと「サーバーが大丈夫と言っている」にすぎず、ブロックチェーンを使う意味が薄れる。

## 影響

- Kotlin・Go・ブラウザでハッシュの計算方法を完全にそろえる必要がある（テストベクタを共有する）
- ブラウザからSepoliaのRPCを呼ぶため、RPCプロバイダを決める必要がある
- 通信障害時の「照合できず」を「不一致」と区別して扱う必要がある
