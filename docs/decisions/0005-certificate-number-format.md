# 0005 証明書番号は手入力できる短い番号にする

- ステータス：提案中
- 日付：2026-10-28
- 関連：FR-16、NFR-06、[data-model.md](../data-model.md)

## 背景

証明書のURLと、買い手が手入力する番号の形式を決める必要がある。出品画像のQRは、それを見ているスマホのカメラでは読めない（スクショからの読み取りは手間）ため、手入力やコピーで開く場面が多い。

## 選択肢

- A：長いランダムID（UUIDなど）
- B：手入力できる短い番号（英数字8〜10文字）

## 決定（案）

Bを採る。具体的にはCrockford Base32の10文字（約50ビット）とし、`XXXXX-XXXXX` の形で表示する。総当たり対策として、Go側でAPIにレート制限をかける。

## 理由

- Crockford Base32は I・L・O・U を使わず、入力時に O を 0、I と L を 1 として読み替えるルールがあるので、FR-16の打ち間違い吸収とそのまま合う
- 10文字あれば約1,100兆通りあり、レート制限と組み合わせれば総当たりで他人の証明書を見つけるのは現実的でない
- 連番にすると他人の証明書を順番に見られてしまうので使わない

## 影響

- Goが番号を発行し、重複しないことを保証する
- Webは入力を正規化（大文字化、ハイフン・空白の除去、O→0、I・L→1）してからAPIを呼ぶ
- 内部IDは別に持ってよいが、Webが扱うのはこの番号だけにする
