# 0009 事業者向けサイトは別リポジトリにし、整備記録の表示はこのリポジトリで行う

- ステータス：提案中
- 日付：2026-10-28
- 関連：FR-18、[architecture.md](../architecture.md)、[security.md](../security.md)

## 背景

メーカー・修理業者が修理・点検記録を書き込む仕組みを作る予定で、発表に向けたプロトタイプも検討している。その画面をこのWebに同居させるか、分けるかを決める必要がある。

## 選択肢

- A：このリポジトリに事業者向けの画面を同居させる
- B：事業者向けサイトを別リポジトリにし、整備記録の表示はこのリポジトリで行う
- C：整備記録の表示部品だけを共有リポジトリに切り出し、買い手向けサイトと事業者向けサイトをそれぞれ別リポジトリにする

## 決定（案）

Bを採る。

## 理由

- このWebは「ログインなし・読み取り専用・誰でも見られる」が前提（[0002](0002-bookmark-in-browser.md)、[security.md](../security.md)）。事業者向けは本人確認・権限・書き込みが中心で、同居させると公開サイトに認証と書き込み口が入り込む
- 使う人と画面の作りが違う。買い手向けはスマホで1件をさっと見る画面、事業者向けはPCで端末を探して記録を入力する業務画面
- 整備記録の表示は証明書詳細の1セクションで、独立した部品ではない。表示だけを切り出す（C）と、デプロイ先を持たない部品だけのリポジトリが増え、パッケージの公開とバージョン合わせの手間が出る

## 影響

- どのサイトもGoとだけ通信し、サイト同士は直接つながない
- 整備記録のデータ形式、ハッシュの仕様（テストベクタ）、APIの型はGoのリポジトリを正とし、両サイトがそれに従う
- 事業者向けサイトは別ドメイン（例：`partner.<ドメイン>`）にし、ログインのCookieを公開サイトと分ける
- 整備記録の表示（FR-18）はこのリポジトリで作る
- 事業者向けサイトの要件は、別の要件定義で決める
- 将来、事業者向けサイトでも証明書を買い手と同じ見た目で表示する必要が出たら、共有UIパッケージかモノレポ化を新しいADRで検討する
