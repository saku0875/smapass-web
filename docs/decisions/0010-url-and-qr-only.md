# 0010 証明書番号をなくし、QRコードとURLだけで開く

- ステータス：提案中
- 日付：2026-10-29
- 関連：FR-01、FR-11、FR-12、FR-16、NFR-04、NFR-06、[features/qr.md](../features/qr.md)
- 置き換え：[0005](0005-certificate-number-format.md)の全体、[0004](0004-marketplace-policy.md)のうち「相談の結果が出るまではA＋Bで作る」の部分

## 背景

[0005](0005-certificate-number-format.md)では、買い手が手入力できる短い証明書番号を決め、[0004](0004-marketplace-policy.md)では、相談の結果が出るまでQR・URLと番号入力を併用することにした。どちらも次の2つへの備えだった。

- フリマの規約でURL・QRが削除される場合
- 出品画像のQRを、出品を見ているスマホ自身では読めない場合

一方でビジネスプランは、フリマ運営者に話を持ちかけ、商品ページへの証明書の公式表示と、URLの正式な掲載を実現することを前提にしている。

## 選択肢

- A：証明書番号を残す（[0005](0005-certificate-number-format.md)のまま）
- B：証明書番号をなくし、QRコードとURLだけで開く

## 決定（案）

Bを採る。証明書は、URLとそのURLを載せたQRコードだけで開く。

URLに含める証明書IDは、推測できないランダムな値にする（案：128ビット、URLで使える英数字と記号の22文字）。正式な形式はGoと決める。IDは画面に文字として表示しない。

## 理由

- フリマ運営者に持ちかける前提のビジネスプランでは、次の状態を目指す。どちらでも買い手はリンクを押すだけで証明書を開けるので、手入力の入口はいらない
  - 商品ページに証明書が公式に表示される
  - URLの掲載が正式に認められ、リンクとして押せる
- 番号のための仕組み（入力欄、打ち間違いの吸収、カード画像の大きな番号）をなくせるので、画面とカード画像が簡単になる
- 手入力を考えなくてよいので、IDを推測できない長さにでき、総当たりで他人の証明書を見られる心配が小さくなる

## 影響

- FR-16（番号入力）を削除する。IDは欠番にして再利用しない
- カード画像に載せるのは、QR・機種・総合評価・発行日・正規のドメインにする。証明書番号と短いURLは載せない（FR-11、NFR-04）
- コピー用テキストは、URLを含む1〜2行にする（FR-12）
- トップは番号の入力欄をなくし、サービスの説明だけにする
- 公式表示やURLの掲載が認められるまでは、URL・QRが規約違反として削除されると、買い手が証明書を開く手段がなくなる。番号という逃げ道はない。デモはフリマ運営者への提案材料として見せる前提にする
- 出品画像のQRは、出品を見ているスマホでは読めない。主な入口は、商品ページと説明文のリンクになる
- 相談の結果、URLの掲載が認められないフリマが出たら、入口を新しいADRで改めて検討する
- 総当たり対策として、APIのレート制限（NFR-06）は残す
