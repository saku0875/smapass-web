# 0011 アプリが取得するデータ項目を見直し、IMEIをアプリから取得する

- ステータス：提案中
- 日付：2026-10-31
- 関連：FR-03、FR-05、NFR-05、[data-model.md](../data-model.md)、[screens.md](../screens.md)
- 置き換え：[0006](0006-listing-link.md)のうち「製造番号は出品者が入力する（出品者申告）」の部分

## 背景

アプリ（Kotlin）が取得するデータ項目が、2026-10-31に次のとおり決まった。これまでの計測値（残容量、消費電力、稼働時間など）は使わない。

| 区分 | 項目 |
| --- | --- |
| 端末そのもののデータ（たまにしか変わらない） | IMEI、メーカー、モデル、端末名、SoC、CPUコア数、RAM容量、ストレージ容量、画面サイズ、画面密度 |
| 定期取得するデータ | Android OSバージョン、SDK、バッテリー温度、バッテリーサイクルカウント、残り電荷（mAh）、推定最大電荷（mAh）、累計起動回数、異常終了の有無、熱的余裕（0〜1） |

項目にIMEIが入ったため、[0006](0006-listing-link.md)で「出品者申告」としていた製造番号の扱いが変わる。

## 選択肢

- A：これまでどおり、製造番号は出品者が出品先と一緒に入力する
- B：アプリが取得したIMEIを端末情報として持ち、その末尾を表示する

## 決定（案）

Bを採る。出品との照合欄には、出品先とあわせてIMEIの末尾4桁を表示する。

## 理由

- 同じ端末の識別番号を、出品者の入力とアプリの取得の2か所で持つと、食い違ったときにどちらを信じるかが分からなくなる
- アプリが取得した値なら、出品者の打ち間違いや偽りの申告を減らせる

## 影響

- 出品先の項目から「製造番号の末尾」を外す。出品先はフリマ名・商品ID・登録日時になる
- Webに渡すのはIMEIの末尾4桁だけにする。全桁はGoから返さない（NFR-05）
- 端末情報は、今のところ改ざん検証（ハッシュ）の対象外として扱う。対象にする場合は、IMEIの全桁が公開の記録データに入らないよう、全桁ではなくハッシュ値などを入れる方式をGoと決める
- 画面の構成と表示方法は [screens.md](../screens.md) のとおりに変える

## 要確認（アプリ担当）

- IMEIの取得方法：Android 10以降、一般のアプリはIMEIを自動では取得できない。利用者の入力になる場合は、Aと同じく「申告」の扱いになり、この決定を見直す
- 端末名の意味：製品コード名（例：shiba）か、利用者が付けた名前（例：「太郎のスマホ」）か。後者なら個人情報になるので表示しない
- 熱的余裕の向き：1に近いほど熱で性能制限がかかりやすい値（Androidの getThermalHeadroom と同じ向き）として表示している。逆の向きなら表示を直す
- OSからの値であることを証明する値が追加される予定があるので、決まったら検証の取り決め（[features/verification.md](../features/verification.md)）に足す
