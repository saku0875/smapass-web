# 0012 ブックマークをなくし、メニューのない画面構成にする

- ステータス：提案中
- 日付：2026-11-05
- 関連：FR-04、FR-13、FR-14、FR-15、FR-19、[screens.md](../screens.md)
- 置き換え：[0002](0002-bookmark-in-browser.md)の全体

## 背景

[0002](0002-bookmark-in-browser.md)では、買い手が複数の出品を見比べるためのブックマークをブラウザに保存することにした。その一覧を開くために、画面にはメニューが必要だった。

一方で、買い手はQRコードやURLから概要画面（FR-19）に直接来るようになり、トップや一覧を経由しなくなった。メニューに残るのは、トップ・ブックマーク・証明書の読み方の3つだけで、どれも常に見せておく必要がない。

## 選択肢

- A：ブックマークとメニューを残す
- B：ブックマークは残し、メニューだけなくす
- C：ブックマークとメニューの両方をなくす

## 決定（案）

Cを採る。画面の移動は、各画面のボタンとリンクだけで行う。

| 画面 | 開き方 |
| --- | --- |
| 概要 | QRコード、URL |
| 詳細 | 概要の「詳細を見る」 |
| 検証の詳細 | 詳細の検証結果にある「詳しく見る」 |
| 証明書の読み方 | 概要の一番下のリンク |
| 出品用素材 | アプリの「出品に使う」ボタン |

## 理由

- 保存先がブラウザなので、フリマアプリやQRコード読み取りアプリの中で開くと保存先が別になることがある。買い手には「保存したのに消えた」ように見える
- メニューをなくすと、ブックマーク一覧を開く入口を別に用意する必要が出る
- 出品を見比べるだけなら、フリマの「いいね」などの機能で足りる
- 画面に出す要素が減り、スマホに詳しくない人にも分かりやすくなる

## 影響

- FR-13、FR-14、FR-15を削除する。IDは欠番にして再利用しない
- `/bookmarks` の画面と、複数証明書の要約を返すAPI（`/api/certificates?ids=`）をなくす。Goに実装を求めない
- 証明書の読み方へのリンクは、概要の一番下に置く（FR-04）
- ログインなしで読み取り専用という前提は変わらない
- 見比べる機能が必要になったら、保存先も含めて新しいADRで改めて検討する
