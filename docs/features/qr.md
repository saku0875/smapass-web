# 出品用素材とQR

出品者がメルカリなどの出品に添えるカード画像・URL・コピー用テキストと、買い手がそれを使って証明書を開く入口（QR・URL・番号入力）の仕様。関連要件はFR-11、FR-12、FR-16、FR-17、NFR-04。

## フリマ規約上の制約

QRコードやURLを出品に添える方式は、フリマ各社の規約とぶつかる可能性がある。特にメルカリは外部サイトへの誘導を禁じ、外部の連絡手段を書く違反の対象にQRコード画像も含めている。証明書URLが違反と判断されるかは事務局次第で、グレーと見ておく。

| フリマ | 関係するルール | Webへの影響 |
| --- | --- | --- |
| メルカリ | SNSなど外部サイトへの誘導を禁止。違反と判断されると商品削除や利用制限の可能性 | URL・QRが削除対象になりうる。証明書番号だけでも開けるようにしておく |
| Yahoo!フリマ | 商品説明文を画像にして載せることを禁止。出品物と関係ない画像やリンクも禁止 | カード画像に文章を詰め込まず、QR・番号・機種・評価程度にとどめる |
| Yahoo!フリマ | 携帯電話は商品説明に製造番号の記載が必要。スマホは工場出荷状態に初期化して出品 | 製造番号を照合に使える。初期化前に証明書を発行しておく必要がある |
| ラクマ | 未確認 | 要確認 |

規約上の扱いは、各フリマ運営者に個別に話を持ち帰って相談する。これをビジネスプランの前提にしている。相談で決まるまでは、デモとMVPをQR・URL＋番号入力の形で作る。経緯とフリマごとの相談状況は [decisions/0004](../decisions/0004-marketplace-policy.md)。

## 出品用素材ページ（`/c/[番号]/share`）

アプリの「出品に使う」ボタンから開く。1画面に次の4つを並べる。

| 要素 | 内容 | 要件 |
| --- | --- | --- |
| カード画像 | プレビューと「画像を保存」ボタン | FR-11 |
| URL | 証明書詳細のURLとコピーボタン | FR-12 |
| 説明文用テキスト | 説明文にそのまま貼れる1〜2行とコピーボタン | FR-12 |
| 出品先の登録状況 | 登録済みならフリマ名と商品ID、未登録なら「出品後にアプリから登録できます」 | FR-05 |

説明文用テキストの例：

```text
端末状態証明書：XXXXX-XXXXX
https://<ドメイン>/c/XXXXX-XXXXX
```

画像の保存は、スマホではWeb Share APIでファイルを共有シートに渡し、写真に保存してもらう形を第一候補にする。使えないブラウザでは画像の長押し保存やダウンロードに切り替える（案）。

## カード画像（`/c/[番号]/card.png`）

出品画像の1枚として使う正方形の画像。載せるのは照会に必要な最小限だけで、説明文は画像にしない。

| 要素 | 内容 | ねらい |
| --- | --- | --- |
| QRコード | 証明書詳細のURL | 別の端末やスクショから読み取る |
| 証明書番号 | 大きめの文字で表示 | QRを読めない人が手入力する |
| 短いURL | ドメイン＋番号 | コピー・手入力用 |
| 機種名・総合評価・発行日 | 各1行 | フリマの一覧で縮小されても何の画像か分かる |

- サイズ：1080×1080px（案）
- 生成：Next.jsの画像生成で作り、OGP画像と仕組みを共用する（[decisions/0007](../decisions/0007-card-image-on-web.md)）
- QR：サーバー内で生成する。誤り訂正レベルはM以上（案）
- 縮小しても証明書番号が読めること（NFR-04）

## 番号入力（トップ）

出品画像のQRは、それを見ているスマホ自身のカメラでは読めない（スクショからの読み取りは手間がかかる）。そのため番号入力を主な入口として扱う。

- 大文字小文字を区別しない
- ハイフンや空白の有無を問わない
- 0とO、1とI・Lは同じ文字として扱う（番号の形式は [decisions/0005](../decisions/0005-certificate-number-format.md)）
- 見つからないときは「近い番号はありません」ではなく、打ち間違いの可能性を案内する

## OGP画像

`/c/[番号]` のURLをSNSやチャットに貼ったときに、機種名と総合評価入りのプレビューを出す（FR-17、Could）。カード画像と同じレイアウト部品から作る。
