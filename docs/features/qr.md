# 出品用素材とQR

出品者がメルカリなどの出品に添えるカード画像・URL・コピー用テキストと、買い手がそれを使って証明書を開く入口（QR・URL）の仕様。関連要件はFR-11、FR-12、FR-17、NFR-04。

## フリマ規約上の制約

QRコードやURLを出品に添える方式は、フリマ各社の規約とぶつかる可能性がある。特にメルカリは外部サイトへの誘導を禁じ、外部の連絡手段を書く違反の対象にQRコード画像も含めている。証明書URLが違反と判断されるかは事務局次第で、グレーと見ておく。

| フリマ | 関係するルール | Webへの影響 |
| --- | --- | --- |
| メルカリ | SNSなど外部サイトへの誘導を禁止。違反と判断されると商品削除や利用制限の可能性 | URL・QRが削除対象になりうる。公式表示とURL掲載の相談で解決する前提（[decisions/0010](../decisions/0010-url-and-qr-only.md)） |
| Yahoo!フリマ | 商品説明文を画像にして載せることを禁止。出品物と関係ない画像やリンクも禁止 | カード画像に文章を詰め込まず、QR・機種・評価程度にとどめる |
| Yahoo!フリマ | 携帯電話は商品説明に製造番号の記載が必要。スマホは工場出荷状態に初期化して出品 | 製造番号を照合に使える。初期化前に証明書を発行しておく必要がある |
| ラクマ | 未確認 | 要確認 |

規約上の扱いは、各フリマ運営者に個別に話を持ち帰って相談する。これをビジネスプランの前提にしている。デモとMVPはQR・URLだけで作り、相談の場で提案材料として見せる（[decisions/0010](../decisions/0010-url-and-qr-only.md)）。経緯とフリマごとの相談状況は [decisions/0004](../decisions/0004-marketplace-policy.md)。

## 出品用素材ページ（`/c/[ID]/share`）

アプリの「出品に使う」ボタンから開く。1画面に次の4つを並べる。

| 要素 | 内容 | 要件 |
| --- | --- | --- |
| カード画像 | プレビューと「画像を保存」ボタン | FR-11 |
| URL | 証明書の概要画面のURLとコピーボタン | FR-12 |
| 説明文用テキスト | 説明文にそのまま貼れる1〜2行とコピーボタン | FR-12 |
| 出品先の登録状況 | 登録済みならフリマ名と商品ID、未登録なら「出品後にアプリから登録できます」 | FR-05 |

説明文用テキストの例：

```text
端末状態証明書（Google Pixel 8）
https://<ドメイン>/c/<証明書ID>
```

画像の保存は、スマホではWeb Share APIでファイルを共有シートに渡し、写真に保存してもらう形を第一候補にする。使えないブラウザでは画像の長押し保存やダウンロードに切り替える（案）。

## カード画像（`/c/[ID]/card.png`）

出品画像の1枚として使う正方形の画像。載せるのは照会に必要な最小限だけで、説明文は画像にしない。

| 要素 | 内容 | ねらい |
| --- | --- | --- |
| QRコード | 証明書の概要画面のURL | 別の端末やスクショから読み取る |
| 機種名・総合評価・発行日 | 各1行 | フリマの一覧で縮小されても何の画像か分かる |
| 正規のドメイン | ドメインのみ | 偽の証明書サイトと見分ける |

- サイズ：1080×1080px（案）
- 生成：Next.jsの画像生成で作り、OGP画像と仕組みを共用する（[decisions/0007](../decisions/0007-card-image-on-web.md)）
- QR：サーバー内で生成する。誤り訂正レベルはM以上（案）
- 縮小しても機種と評価が読めること（NFR-04）

## OGP画像

`/c/[ID]` のURLをSNSやチャットに貼ったときに、機種名と総合評価入りのプレビューを出す（FR-17、Could）。カード画像と同じレイアウト部品から作る。
