# 要件

## 目的

Webフロントの主役は、出品者がメルカリなどの出品画像や説明文に添えるQRコード・URLと、そこから買い手が開く証明書ページ。データ取得と公開設定はKotlinアプリ、保存と評価はGoバックエンドが担い、Webは「出品に添える素材を作る・見せる・確かめる」を受け持つ。

## ユーザー

| ユーザー | 目的 | 主な入口 | MVP |
| --- | --- | --- | --- |
| 買い手（中古端末を検討中） | 出品中の端末の状態と、記録が改ざんされていないかを確かめる | 商品ページや説明文のURL、出品画像のQRコード | 対象 |
| 出品者（アプリ利用者） | 出品に添えるカード画像・URL・説明文用テキストを手に入れる | アプリの「出品に使う」ボタン | 対象 |
| フリマ運営者 | 商品ページに証明書を公式に表示する | 提携による埋め込み・API | 将来 |
| メーカー・修理業者 | 修理・点検記録を書き込む | 事業者向けサイト（別リポジトリ、[decisions/0009](decisions/0009-partner-site-separate-repo.md)） | このリポジトリでは対象外 |

## スコープ

- 対象：出品用素材（カード画像・URL・コピー用テキスト）の提供、証明書の閲覧、改ざん検証
- 対象外（他チームの担当）：端末データの取得と公開設定（アプリ）、評価の算出（バックエンド）

## 機能要件（FR）

Mustは6件。買い手側は「開く→読む→確かめる」、出品者側は「カード画像を手に入れて出品に添える」が一通りできる。

| FR-02 | 閲覧 | 評価サマリー | 総合評価（例：A〜D）と項目ごとの評価、その根拠を文章で表示 | Must |

## 非機能要件（NFR）

| ID | 区分 | 要件 |
| --- | --- | --- |
| NFR-01 | 対応端末 | スマホ優先のレスポンシブ。幅360pxで崩れないこと |
| NFR-02 | 表示速度 | 概要画面と詳細画面はサーバー側で描画し、検証はページ表示後に非同期で実行する |
| NFR-03 | 障害時 | RPCやAPIが落ちても証明書本体は表示し、「照合できませんでした（再試行）」を「不一致」と区別して出す |
| NFR-04 | カード画像 | 正方形。フリマの一覧で縮小されても機種が読める文字サイズにし（評価は Back の実装後に足す）、文章は載せない |
| NFR-05 | 個人情報 | 製造番号（IMEI）は全桁を表示しない（現在は末尾も表示しない）。照合に入力されたIMEIはページURLやWebのサーバーを通さない。証明書ページは検索エンジンに載せない（noindex） |
| NFR-06 | セキュリティ | 端末IDの総当たり対策として、APIのレート制限をバックエンド側で行う |
| NFR-07 | アクセシビリティ | 評価を色だけで表さない。グラフには数値の代替表示を付ける |
| NFR-08 | 言語 | 日本語のみ |

技術の選定は [architecture.md](architecture.md)、セキュリティの詳細は [security.md](security.md)。

## 受入条件

各FR/NFRを「完了」とみなす条件の案。テストを書くときの基準にする。

### 閲覧

- FR-01：有効なIDで `/certificates/[ID]` を開くと、JavaScriptを無効にしても機種名・最終計測日時・記録期間・記録回数が表示される。存在しない・非公開・形式が不正なIDでは「見つからないか、非公開に設定されています」と表示し、HTTPステータスは404。Back が 429・5xx を返すか通信できないときは「一時的に表示できません」と表示する
- FR-02：総合評価と項目別評価が表示され、各項目に説明文が1文以上ある。Back が評価を返すまでは「評価は準備中」と表示し、仮の値で埋めない
- FR-03：推定最大電荷・バッテリー温度・熱的余裕の推移と1週間あたりの起動回数が、記録日時を横軸に表示される
- FR-04：概要画面の一番下に /about へのリンクがある
- FR-05：正しいIMEIを入力すると「この証明書の端末です」、別の公開端末のIMEIでは「別の端末の証明書です」、見つからなければ「確認できませんでした」、通信エラーでは「照合できず」と表示する。照合の前後でIMEIがページURLやWebのサーバーへのリクエストに含まれない
- FR-06：記録日時を一覧でき、記録の間隔が一定以上空いた期間が明示される（しきい値は要決定。決まるまでは最も空いた間隔を事実として出し、途切れたかどうかは断定しない）
- FR-18：整備記録がある証明書では、記録者・日時・内容が表示され、アプリの自動記録と見分けがつく。整備記録がない証明書では「整備記録はありません」と表示する
- FR-19：`/certificates/[ID]` を開くと概要画面が出て、最終計測日時・検証結果・IMEIの照合欄・評価（準備中）が表示される。グラフと記録の表は出ない。「詳細を見る」を押すと `/certificates/[ID]/details` に移る。JavaScriptを無効にしても、検証結果とIMEIの照合以外は表示される

### 検証

- FR-08：ページ表示後に検証が走り、「一致」「不一致」「照合できず」のいずれかが表示される。データを1文字変えたテストデータ、途中の記録を消したテストデータでは「不一致」になる。APIやRPCへの通信を遮断すると「照合できず」になり、「不一致」とは表示されない。記録がまだチェーンに記録されていない間とデモの記録は「照合できず」になり、「一致」「改ざんなし」とは表示されない
- FR-09：各記録の連番・ハッシュ・記録時刻・チェーンへの記録状態が表示される。チェーンが決まったら、トランザクションハッシュとエクスプローラーのリンクを足す
- FR-10：ダウンロードしたJSON（Back が返す canonical_payload そのもの）のSHA-256が、画面に出ているハッシュと一致する

### 出品

- FR-11：`/certificates/[ID]/card.png` が正方形のPNGを返し、QRを読み取ると概要画面が開く。機種名・最終計測日・正規のドメインが載っていて、端末IDは文字として載っていない。発行日は載せない。スマホで画像を端末に保存できる
- FR-12：ボタン1つで、証明書のURLを含む1〜2行がクリップボードに入る

### 共通

- FR-17：`/certificates/[ID]` のURLをSNSやチャットに貼ると、機種名と最終計測日入りのプレビューが出る

### 非機能

- NFR-01：幅360pxで横スクロールが出ない
- NFR-03：APIまたはRPCを止めた状態でも概要画面と詳細画面が表示され、検証欄が「照合できず」になる
- NFR-04：カード画像を一覧サイズ（例：幅200px程度）に縮小しても機種名が読める（評価は Back の実装後に足す）
- NFR-05：どの画面にもIMEIの全桁が出ない（照合後は入力欄も空にする）。証明書ページのHTMLに `noindex` がある
- NFR-07：評価バッジは文字を含み、グラフには同じ値の表が付く

## スコープ外

MVPではやらないもの。

- 商品ページへの公式表示・埋め込み。ビジネスプランでは各フリマ運営者に話を持ち帰って相談し、その結果に応じて作る（ビジネスモデルのパターン1）→ [decisions/0004](decisions/0004-marketplace-policy.md)
- 整備記録の書き込み。メーカー・修理業者向けの別リポジトリのサイトで行う（[decisions/0009](decisions/0009-partner-site-separate-repo.md)）。記録者ごとの信頼度の付け方もそちらの要件定義で決め、決まったらこのWebでの表示を足す
- 証明書番号と番号入力。証明書はQRコードとURLだけで開く（[decisions/0010](decisions/0010-url-and-qr-only.md)）
- ブックマークと、複数の証明書を見比べる機能（[decisions/0012](decisions/0012-remove-bookmark-and-sidebar.md)）
- 発行手数料の決済（ビジネスモデルのパターン2）
- Web上での書き込み操作全般（出品先の登録はアプリで行う）
- 日本語以外の言語
