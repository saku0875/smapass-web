# 要件

## 目的

Webフロントの主役は、出品者がメルカリなどの出品画像や説明文に添えるQRコード・URL・証明書番号と、そこから買い手が開く証明書ページ。データ取得と発行はKotlinアプリ、保存と評価はGoバックエンドが担い、Webは「出品に添える素材を作る・見せる・確かめる・比べる」を受け持つ。

## ユーザー

| ユーザー | 目的 | 主な入口 | MVP |
| --- | --- | --- | --- |
| 買い手（中古端末を検討中） | 出品中の端末の状態と、記録が改ざんされていないかを確かめる | 出品画像のQRコード、説明文の証明書番号・URL | 対象 |
| 出品者（アプリ利用者） | 出品に添えるカード画像・URL・説明文用テキストを手に入れる | アプリの「出品に使う」ボタン | 対象 |
| フリマ運営者 | 商品ページに証明書を公式に表示する | 提携による埋め込み・API | 将来 |
| メーカー・修理業者 | 修理・点検記録を書き込む | 事業者向けサイト（別リポジトリ、[decisions/0009](decisions/0009-partner-site-separate-repo.md)） | このリポジトリでは対象外 |

## スコープ

- 対象：出品用素材（カード画像・URL・コピー用テキスト）の提供、証明書の閲覧、改ざん検証、ブックマーク
- 対象外（他チームの担当）：端末データの取得と証明書の発行（アプリ）、評価の算出（バックエンド）

## 機能要件（FR）

Mustは8件。買い手側は「開く→読む→確かめる→保存する」、出品者側は「カード画像を手に入れて出品に添える」が一通りできる。

| ID | 区分 | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- | --- |
| FR-01 | 閲覧 | 証明書の表示 | 証明書番号で証明書を取得し、サーバー側で描画して表示 | Must |
| FR-02 | 閲覧 | 評価サマリー | 総合評価（例：A〜D）と項目ごとの評価、その根拠を文章で表示 | Must |
| FR-03 | 閲覧 | 推移グラフ | バッテリー残容量・温度などの推移を折れ線で表示 | Must |
| FR-04 | 閲覧 | 初めての人向けの説明 | 証明書詳細の冒頭に「この証明書は何か」を1〜2行で表示し、/about へリンク | Should |
| FR-05 | 閲覧 | 出品先の表示 | 出品者が登録した出品（フリマ名と商品ID）を表示し、開いている出品と同じか確かめられる | Should |
| FR-06 | 閲覧 | 記録タイムライン | 記録日時の一覧と、記録が途切れた期間を明示 | Should |
| FR-07 | 閲覧 | 失効の表示 | 失効・再発行済みの証明書には警告を出し、新しい証明書へ誘導 | Should |
| FR-08 | 検証 | ワンクリック検証 | ブラウザでデータ本体のハッシュを再計算し、Sepolia上の記録と照合。「一致・不一致・照合できず」を区別して表示 | Must |
| FR-09 | 検証 | 検証の詳細 | 記録ごとのハッシュ、トランザクションハッシュ、記録時刻、Etherscanリンク | Should |
| FR-10 | 検証 | 生データのダウンロード | 正規化済みJSONを保存でき、第三者が自分で検証できる | Could |
| FR-11 | 出品 | カード画像の生成 | QR・証明書番号・短いURL・機種・評価を載せた正方形の画像を生成し、端末に保存できる | Must |
| FR-12 | 出品 | コピー用テキスト | 説明文に貼る1〜2行（証明書番号とURL）をワンタップでコピー | Should |
| FR-13 | ブックマーク | 追加・削除 | 証明書詳細からワンタップで追加・削除 | Must |
| FR-14 | ブックマーク | 一覧 | 機種・評価・残容量・出品先をカード表示して並べ替え。どの出品かをメモで残せる | Must |
| FR-15 | ブックマーク | 比較 | 2〜3件を選んで項目を横並びで比較 | Could |
| FR-16 | 共通 | 番号入力 | トップで証明書番号を入れて開く。大文字小文字やハイフンの有無を問わず、0とO、1とIの打ち間違いを吸収 | Must |
| FR-17 | 共通 | OGP画像 | URLを貼ったときに機種と評価がプレビューに出る（カード画像と仕組みを共用） | Could |
| FR-18 | 閲覧 | 整備記録の表示 | 事業者が記録した修理・点検の記録を、記録者（事業者名と種別）・日時・内容とともに表示する。アプリの自動記録と見分けがつくようにする | Should |

画面との対応は [screens.md](screens.md)、出品用素材と番号入力の詳細は [features/qr.md](features/qr.md)、検証の詳細は [features/verification.md](features/verification.md)。

## 非機能要件（NFR）

| ID | 区分 | 要件 |
| --- | --- | --- |
| NFR-01 | 対応端末 | スマホ優先のレスポンシブ。幅360pxで崩れないこと |
| NFR-02 | 表示速度 | 証明書詳細はサーバー側で描画し、検証はページ表示後に非同期で実行する |
| NFR-03 | 障害時 | RPCやAPIが落ちても証明書本体は表示し、「照合できませんでした（再試行）」を「不一致」と区別して出す |
| NFR-04 | カード画像 | 正方形。フリマの一覧で縮小されても証明書番号が読める文字サイズにし、文章は載せない |
| NFR-05 | 個人情報 | 製造番号は末尾のみ表示。証明書ページは検索エンジンに載せない（noindex） |
| NFR-06 | セキュリティ | 証明書番号の総当たり対策として、APIのレート制限をバックエンド側で行う |
| NFR-07 | アクセシビリティ | 評価を色だけで表さない。グラフには数値の代替表示を付ける |
| NFR-08 | 言語 | 日本語のみ |

技術の選定は [architecture.md](architecture.md)、セキュリティの詳細は [security.md](security.md)。

## 受入条件

各FR/NFRを「完了」とみなす条件の案。テストを書くときの基準にする。

### 閲覧

- FR-01：有効な番号で `/c/[番号]` を開くと、JavaScriptを無効にしても機種名・総合評価・証明書情報が表示される。存在しない番号ではエラー表示になり、HTTPステータスは404
- FR-02：総合評価と項目別評価が表示され、各項目に説明文が1文以上ある
- FR-03：バッテリー残容量と温度の推移が、記録日時を横軸に表示される
- FR-04：証明書詳細の最初の画面内に、説明1〜2行と /about へのリンクがある
- FR-05：出品先が登録されていればフリマ名と商品IDを表示し、未登録なら「出品先は登録されていません」と表示する
- FR-06：記録日時を一覧でき、記録の間隔が一定以上空いた期間が明示される（しきい値は要決定）
- FR-07：失効・再発行済みの証明書を開くと内容より上に警告が出る。再発行の場合は新しい証明書へのリンクがある
- FR-18：整備記録がある証明書では、記録者・日時・内容が表示され、アプリの自動記録と見分けがつく。整備記録がない証明書では「整備記録はありません」と表示する

### 検証

- FR-08：ページ表示後に検証が走り、「一致」「不一致」「照合できず」のいずれかが表示される。データを1文字変えたテストデータでは「不一致」になる。RPCへの通信を遮断すると「照合できず」になり、「不一致」とは表示されない
- FR-09：各記録のハッシュ・トランザクションハッシュ・記録時刻が表示され、Sepolia版Etherscanのリンクが開ける
- FR-10：ダウンロードしたJSONのSHA-256が、画面に出ているハッシュと一致する

### 出品

- FR-11：`/c/[番号]/card.png` が正方形のPNGを返し、QRを読み取ると証明書詳細が開く。証明書番号・短いURL・機種名・総合評価・発行日が載っている。スマホで画像を端末に保存できる
- FR-12：ボタン1つで「証明書番号＋URL」の1〜2行がクリップボードに入る

### ブックマーク

- FR-13：証明書詳細から1タップで追加・削除でき、ページを再読み込みしても状態が保たれる
- FR-14：`/bookmarks` に保存した証明書がカードで並び、評価順・発行日順で並べ替えられる。各カードにメモを残せる
- FR-15：2〜3件を選ぶと主要項目が横並びで表示される

### 共通

- FR-16：大文字小文字・ハイフンの有無・0とO・1とIの違いがあっても同じ証明書が開く。見つからないときは打ち間違いの可能性を案内する
- FR-17：`/c/[番号]` のURLをSNSやチャットに貼ると、機種名と総合評価入りのプレビューが出る

### 非機能

- NFR-01：幅360pxで横スクロールが出ない
- NFR-03：APIまたはRPCを止めた状態でも証明書詳細が表示され、検証欄が「照合できず」になる
- NFR-04：カード画像を一覧サイズ（例：幅200px程度）に縮小しても証明書番号が読める
- NFR-05：どの画面にも製造番号の全桁が出ない。証明書ページのHTMLに `noindex` がある
- NFR-07：評価バッジは文字を含み、グラフには同じ値の表が付く

## スコープ外

MVPではやらないもの。

- 商品ページへの公式表示・埋め込み。ビジネスプランでは各フリマ運営者に話を持ち帰って相談し、その結果に応じて作る（ビジネスモデルのパターン1）→ [decisions/0004](decisions/0004-marketplace-policy.md)
- 整備記録の書き込み。メーカー・修理業者向けの別リポジトリのサイトで行う（[decisions/0009](decisions/0009-partner-site-separate-repo.md)）。記録者ごとの信頼度の付け方もそちらの要件定義で決め、決まったらこのWebでの表示を足す
- アカウントによるブックマーク同期（[decisions/0002](decisions/0002-bookmark-in-browser.md) の案B）
- 発行手数料の決済（ビジネスモデルのパターン2）
- Web上での書き込み操作全般（出品先の登録はアプリで行う）
- 日本語以外の言語
