# セキュリティ

このサービスが保証するのは「記録後にデータが改ざんされていないこと」まで。計測値そのものの正しさや、記録外の期間の扱い、出品先の正しさはブロックチェーンでは保証しない。画面ではこの線引きを隠さずに伝える。

## 信頼モデル

| 対象 | 保証の仕組み | 保証の強さ |
| --- | --- | --- |
| 記録データが後から書き換えられていないこと | Sepoliaに刻んだハッシュとブラウザで照合（[features/verification.md](features/verification.md)） | 強い。運営者を信用しなくても確かめられる |
| 計測値そのものが正しいこと | アプリが端末から取得 | 保証しない。端末やアプリが細工されていれば防げない |
| 記録が途切れた期間の使われ方 | なし | 保証しない。期間を画面に明示する（FR-06） |
| 出品先・製造番号 | アプリからしか登録できない（本人確認） | 中程度。チェーンには載らず、運営者のDBに依存する。製造番号は出品者の申告 |
| 評価 | バックエンドの算出ロジック | 根拠を文章で示す（FR-02）。評価そのものは運営者の判断 |

Sepoliaはテストネットであることを画面に明記する。

## 脅威と対策

| 脅威 | 対策 | 担当 |
| --- | --- | --- |
| 他人の証明書を流用して出品する | 出品先と製造番号の末尾を最初の画面に表示し（FR-05）、届いた端末と照合してもらう | Web・アプリ |
| 証明書番号を総当たりして他人の証明書を見る | 番号を十分長くし（[decisions/0005](decisions/0005-certificate-number-format.md)）、APIにレート制限をかける（NFR-06） | Go |
| 記録データの改ざん（運営者自身を含む） | ブラウザでの検証（[decisions/0001](decisions/0001-verify-in-browser.md)） | Web |
| 通信障害を「不一致」と誤表示して信用を落とす | 「照合できず」を別の状態として扱う（NFR-03） | Web |
| 偽の証明書サイトに誘導される | カード画像に正規のドメインを載せ、/about で正規のURLを案内する | Web |
| 個人情報の露出 | 製造番号は末尾のみ表示し、証明書ページは noindex にする（NFR-05）。取得データ以外は表示しない | Web・Go |
| 出品先を勝手に書き換えられる | 登録・変更はアプリからのみ。Webには書き込みAPIを置かない | アプリ・Go |
| QRの生成元に証明書URLが漏れる | QRはサーバー内で生成し、外部のQR生成サービスを使わない | Web |

## 認証・認可

- MVPのWebにログインはない。すべての画面は証明書番号を知っていれば誰でも見られる
- Webは読み取り専用。証明書の発行・失効・出品先の登録などの書き込みは、本人確認済みのアプリからのみ行う
- ブックマークはブラウザ内に保存するため、サーバー側の認証はいらない（[decisions/0002](decisions/0002-bookmark-in-browser.md)）
- アカウントを導入する場合（案B）は `auth.md` を新設し、この節をそちらへ移す
