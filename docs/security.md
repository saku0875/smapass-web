# セキュリティ

このサービスが保証するのは「記録後にデータが改ざんされていないこと」まで。計測値そのものの正しさや、記録外の期間の扱い、出品先の正しさはブロックチェーンでは保証しない。画面ではこの線引きを隠さずに伝える。

## 信頼モデル

| 対象 | 保証の仕組み | 保証の強さ |
| --- | --- | --- |
| 記録データが後から書き換えられていないこと | ブロックチェーンに刻んだハッシュとブラウザで照合（[features/verification.md](features/verification.md)）。チェーンへの記録は未実装で、今は保存されたハッシュと記録のつながりだけを確かめる | チェーン照合ができれば強い（運営者を信用しなくても確かめられる）。今は運営者のサーバーに依存するので、「改ざんなし」とは表示しない |
| 計測値そのものが正しいこと | アプリが端末から取得 | 保証しない。端末やアプリが細工されていれば防げない |
| 記録が途切れた期間の使われ方 | なし | 保証しない。最も空いた間隔を画面に出す（FR-06。欠測のしきい値は未決） |
| 出品先・端末情報（IMEIを含む） | アプリからしか登録・取得できない（本人確認） | 中程度。チェーンには載らず、運営者のDBに依存する（[decisions/0011](decisions/0011-device-data-items.md)） |
| 評価 | バックエンドの算出ロジック | 根拠を文章で示す（FR-02）。評価そのものは運営者の判断 |

チェーンが決まり、テストネットを使う場合は画面に明記する。ページは最後に届いた記録までの内容で、リアルタイムの端末の状態ではないことも明記する（[decisions/0014](decisions/0014-show-latest-device-state.md)）。

## 脅威と対策

| 脅威 | 対策 | 担当 |
| --- | --- | --- |
| 他人の証明書を流用して出品する | 届いた端末のIMEIを入力して、この証明書の端末か照合してもらう（FR-05、[decisions/0015](decisions/0015-imei-input-check.md)）。出品先の表示は Back の実装待ち | Web・アプリ・Go |
| 端末IDを総当たりして他人の証明書を見る | IDをランダムな UUID にし（[decisions/0013](decisions/0013-device-uuid-url.md)）、APIにレート制限をかける（NFR-06）。非公開の端末は 404 にする | Go |
| 記録データの改ざん（運営者自身を含む） | ブラウザでの検証（[decisions/0001](decisions/0001-verify-in-browser.md)） | Web |
| 通信障害を「不一致」と誤表示して信用を落とす | 「照合できず」を別の状態として扱う（NFR-03） | Web |
| 偽の証明書サイトに誘導される | カード画像に正規のドメインを載せ、/about で正規のURLを案内する | Web |
| 個人情報の露出 | IMEIは表示しない。照合で入力されたIMEIはブラウザから Back に直接送り、ページURLやWebのサーバーのログに残さない。証明書ページは noindex にする（NFR-05）。取得データ以外は表示しない | Web・Go |
| 出品先を勝手に書き換えられる | 登録・変更はアプリからのみ。Webには書き込みAPIを置かない | アプリ・Go |
| QRの生成元に証明書URLが漏れる | QRはサーバー内で生成し、外部のQR生成サービスを使わない | Web |

## 認証・認可

- MVPのWebにログインはない。すべての画面は証明書のURLを知っていれば誰でも見られる
- Webは読み取り専用。公開・非公開の切り替えや出品先の登録などの書き込みは、本人確認済みのアプリからのみ行う
- 端末を見られるかどうかは Back が公開設定で決める。URL（UUID）はアクセス権ではない
- ログインが必要な機能を足す場合は `auth.md` を新設し、この節をそちらへ移す
