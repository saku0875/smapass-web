# 業務の流れ

Webの出番は「出品用素材」と「証明書」の2か所。出品者はアプリで発行してWebで素材を受け取り、買い手はフリマの出品からWebの証明書の概要画面に来て、必要なら詳細画面に進む。

## 出品から購入・受け取りまで

```mermaid
sequenceDiagram
    actor S as 出品者
    participant A as アプリ（Kotlin）
    participant G as バックエンド（Go）
    participant C as Sepolia
    participant W as Web（Next.js）
    participant F as フリマ
    actor B as 買い手

    loop 使用中（定期的）
        A->>G: 端末の状態を記録して送信
        G->>C: ハッシュと時刻を記録
    end
    S->>A: 証明書を発行（端末の初期化より前に）
    A->>G: 発行
    G-->>A: 証明書ID
    S->>W: アプリの「出品に使う」から出品用素材を開く
    W-->>S: カード画像・URL・コピー用テキスト
    S->>F: 画像と説明文に添えて出品
    S->>A: （任意）出品URLを登録
    A->>G: 出品先を保存
    B->>F: 出品を見る
    B->>W: リンクやQRで概要画面を開く（必要なら詳細画面へ）
    W->>G: 証明書と記録データを取得
    W->>C: 記録されたハッシュを読む
    W-->>B: 評価・検証結果・出品先を表示
    B->>F: 購入
    B->>B: 届いた端末のIMEIを証明書の末尾と照合
```

## 各段階のポイント

1. 記録：アプリが定期的に端末の状態を記録し、ハッシュと時刻をSepoliaに刻む。Webは関与しない
2. 発行：スマホは工場出荷状態に初期化して出品するのが前提なので、初期化より前に発行を済ませる。アプリ側で案内する
3. 出品用素材の取得：アプリの「出品に使う」ボタンで `/c/[ID]/share` を開き、カード画像を保存してテキストをコピーする（[features/qr.md](features/qr.md)）
4. 出品：カード画像を出品画像の1枚に、URLを説明文に添える。フリマの規約上の扱いは [decisions/0004](decisions/0004-marketplace-policy.md)
5. 出品先の登録（任意）：出品後、アプリから出品URLを登録する。IMEIはアプリが端末情報として取得する（[decisions/0011](decisions/0011-device-data-items.md)）。他人の証明書の流用対策になる（[decisions/0006](decisions/0006-listing-link.md)）
6. 閲覧と検証：買い手は商品ページや説明文のリンクを押すか、別の端末でQRを読んで開く。検証はページ表示後にブラウザで走る（[features/verification.md](features/verification.md)）
7. 受け取り後の照合：届いた端末のIMEIを、証明書に出ている末尾と比べる

## 例外の流れ

| 場面 | Webの振る舞い |
| --- | --- |
| URLが途中で切れている | 「証明書が見つかりません」と表示し、出品ページのリンクから開き直すよう案内する |
| 証明書が失効・再発行済み | 内容の上に警告を出し、再発行なら新しい証明書へのリンクを出す |
| APIやRPCが落ちている | 取得できた範囲で証明書を表示し、検証欄を「照合できず（再試行）」にする |
| 検証が「不一致」 | どの記録が一致しなかったかを示し、/about の説明へ誘導する |
| 他人の証明書が流用されている | Webには買い手がどの出品から来たか分からないので、出品先を最初の画面に出し、買い手に開いている出品と比べてもらう |
